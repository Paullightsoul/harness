# Конституция проекта

Эти правила обязательны для всех агентов. Нарушение = задача не принята.

## Язык и стиль
- Стек проекта определяется его профилем `.harness/project.toml` (`language`, `canon`).
  Конкретику по стеку бери из language-overlay (`.cursor/rules/10-lang-*.md`).
- Форматирование, линт, типы, тесты — те инструменты, что заданы гейтами проекта
  в `.harness/project.toml`. Не предполагай Python по умолчанию — смотри профиль.
- Любая новая логика покрыта тестом так, чтобы её проверял хотя бы один гейт.

## Заземление (анти-галлюцинации)
- НЕ выдумывай API, функции, поля, импорты. Если не уверен — **прочитай реальный файл** или открой документацию через MCP.
- Прежде чем использовать модуль/функцию, убедись что она существует в репозитории или в установленных зависимостях.
- При ссылке на код указывай путь и имя символа (например `src/db/users.py:get_user`).
- Если для задачи не хватает контекста — НЕ додумывай. Останови работу и опиши, чего не хватает, в `reviews/`.

## Definition of Done (общий)
Задача считается выполненной ТОЛЬКО когда:
1. Код реализует ВСЕ acceptance criteria из спеки задачи.
2. ВСЕ гейты проекта из `.harness/project.toml` зелёные (lint/types/test/build — что задано).
3. Нет закомментированного мусора, отладочных логов, TODO без тикета.
4. Изменения минимальны и затрагивают только то, что относится к задаче.

## Границы
- Не трогай файлы вне списка `Файлы` в спеке задачи без явной причины (опиши её).
- Не меняй конфиги CI, секреты, зависимости без указания в задаче.
- Не выполняй деструктивные команды (`rm -rf`, force-push в main, удаление веток).
- **Не правь защищённую зону приёмки** (`tests/spec/**` и то, что задано `PROTECTED_PATHS`).
  Спеки/acceptance пишет оркестратор/ревьюер. Правка этой зоны = автоматический CHANGES
  (anti-gaming guard), задача не принимается.

## Git
- Один таск = одна ветка `task/<id>`. Коммит атомарный, сообщение в формате
  `task(<id>): <краткое описание>`.
- Не мержит сам воркер — мерж делает оркестратор после APPROVE ревьюера.
