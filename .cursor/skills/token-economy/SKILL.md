# Token Economy — экономия контекста

Воркер harness работает в автоматическом цикле. Каждый лишний токен — это:
- Расход бюджета (CostGovernor считает кредиты).
- Раздутый контекст → деградация качества на поздних попытках.
- Замедление цикла worker → gates → reviewer.

## Принципы

### 1. Сжатый вывод
```
НЕЛЬЗЯ: «Отлично! Я проанализировал задачу и считаю, что нам нужно...
         Давайте начнём с создания файла... Вот что я предлагаю сделать...»

НУЖНО:  [действие] → [результат] → [статус гейтов]
```

### 2. Код без комментариев-нарратива
```python
# НЕЛЬЗЯ:
# Здесь мы создаём экземпляр сервиса пользователей
user_service = UserService(db)
# Теперь вызываем метод создания пользователя
result = await user_service.create(data)

# НУЖНО:
user_service = UserService(db)
result = await user_service.create(data)
```

Комментарии только для **why**, никогда для **what**.

### 3. Не дублируй спеку в выводе
Воркер получает спеку задачи в промпте. Не нужно копировать её в ответ
или пересказывать acceptance criteria. Просто реализуй.

### 4. Читай прицельно
```
НЕЛЬЗЯ: Read(path) целиком для файла на 500 строк, когда нужна одна функция.
НУЖНО:  Grep("def target_func", path) → Read(path, offset=N, limit=20)
```

### 5. Не объясняй изменения
```
НЕЛЬЗЯ: «Я изменил строку 42, потому что старая реализация не учитывала...
         Новая реализация лучше тем, что...»

НУЖНО:  [StrReplace] → [прогон гейтов] → [результат]
```

## Шаблон вывода воркера

```
Изменённые файлы:
- src/services/user.py (create, update)
- tests/test_user.py (test_create, test_update)

Гейты:
- ruff check: PASS
- mypy: PASS
- pytest: PASS (12 passed)
```

## Экономия контекста при чтении

| Задача | Плохо | Хорошо |
|--------|-------|--------|
| Найти функцию | Read весь файл | Grep → Read нужный фрагмент |
| Понять API | Read 3 файла | Grep сигнатуры → Read по 10 строк |
| Проверить импорт | Read файл | rg "from X import" --type py |
| Найти использования | Read все файлы | rg "func_name" -l |

## Связь с harness

- **BudgetGovernor** считает кредиты. Экономия токенов = больше попыток
  в рамках бюджета.
- **Лестница эскалации**: auto (дешёвый) → kimi → glm. На auto экономия
  критична: маленький контекст, каждый токен на счету.
- **Фидбэк ревьюера** инжектится в следующую попытку. Компактный вывод
  воркера = больше места для фидбэка в контексте.
