# Search-First — исследуй, потом кодируй

Воркер обязан искать существующую реализацию **до** написания нового кода.
Правило «reuse over reinvent» из конституции workspace `/home/.cursorrules`.

## Когда активировать

- Начинаешь реализацию новой функции / утилиты / абстракции.
- Добавляешь зависимость или интеграцию.
- Спека задачи требует «добавить X» — и ты собираешься писать с нуля.

## Workflow

```
1. АНАЛИЗ ПОТРЕБНОСТИ
   Что конкретно нужно? Язык, фреймворк, ограничения из профиля проекта.

2. ПОИСК (параллельный)
   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
   │  В репозитории │  │ В зависимостях │  │  В workspace  │
   │  rg / Grep     │  │  pip/npm list   │  │ /home/projects│
   └──────────────┘  └──────────────┘  └──────────────┘

3. ОЦЕНКА
   Найденное решение: подходит целиком? частично? не подходит?

4. РЕШЕНИЕ
   ┌──────────┐  ┌──────────┐  ┌──────────┐
   │  Reuse   │  │  Extend  │  │  Build   │
   │  as-is   │  │  /Wrap   │  │  Custom  │
   └──────────┘  └──────────┘  └──────────┘
```

## Обязательные шаги для воркера

### 1. Поиск в репозитории
```bash
rg -l "имя_функции\|паттерн" --type py   # или --type ts
```
Ищи: существующие хелперы, утилиты, аналогичные модули.

### 2. Поиск в зависимостях
```bash
pip list | grep relevant    # Python
npm ls | grep relevant      # TS/JS
```
Проверь — может, нужное уже установлено.

### 3. Поиск в workspace (/home/projects/)
```bash
rg "паттерн" /home/projects/ --type py -l
```
Каноническая реализация может быть в другом сервисе (см. `shared-context/`).

### 4. Поиск в shared-context
Проверь `shared-context/architecture-patterns.md` — есть ли каноническая реализация.

## Матрица решений

| Сигнал | Действие |
|--------|----------|
| Точное совпадение в репо/зависимостях | **Reuse** — импорт и использование |
| Частичное совпадение | **Extend** — тонкая обёртка |
| Ничего не найдено | **Build** — писать, но осознанно |

## Анти-паттерны

- Писать утилиту без поиска → нарушение «reuse over reinvent».
- Не проверить зависимости → дублирование функционала.
- Копировать код из другого сервиса вместо import/extract.
- Ставить тяжёлый пакет ради одной мелкой функции.

## Связь с harness

Этот скилл выполняется **внутри** шага RUNNING (worker). Если поиск показал,
что задача решается переиспользованием — воркер реализует через import, а не
с нуля. Гейты проекта подтвердят корректность.
