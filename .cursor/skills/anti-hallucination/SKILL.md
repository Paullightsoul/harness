# Anti-Hallucination — заземление воркера

4 жёстких правила, которые предотвращают типичные LLM-ошибки. Воркер harness
обязан следовать им на каждой задаче.

## Правило 1: Прочитай, прежде чем менять

**Перед любым изменением файла — открой и прочитай его.**

```
НЕЛЬЗЯ: «Я знаю, что там функция get_user()» → менять файл вслепую.
НУЖНО:  Read(path) → убедиться, что функция существует → менять.
```

Проверяй:
- Существует ли файл по этому пути?
- Существует ли функция/класс/метод с этим именем?
- Какие аргументы принимает? Какой тип возвращает?
- Какие импорты уже есть?

## Правило 2: Не выдумывай API

**Если ты не прочитал определение — ты не знаешь API.**

```
НЕЛЬЗЯ: from app.utils import validate_email  # а существует ли она?
НУЖНО:  rg "def validate_email" --type py     # найди реальное определение
```

Проверяй:
- Функции и классы — через `rg` или `Grep` по кодовой базе.
- Пакеты — через `pip show package` / `npm ls package`.
- Аргументы стандартной библиотеки — через документацию, не по памяти.

## Правило 3: Минимальные изменения

**Делай ровно то, что просит спека. Не больше.**

```
НЕЛЬЗЯ: «Раз уж я тут, добавлю кеширование и обработку ошибок...»
НУЖНО:  Только acceptance criteria из спеки задачи.
```

Почему:
- Лишний код = лишние баги = лишние попытки = лишний бюджет.
- Harness считает бюджет — оверинжиниринг его сжигает.
- Ревьюер отклонит изменения вне scope задачи.

## Правило 4: Признай незнание

**Если не уверен — останови работу, а не додумывай.**

```
НЕЛЬЗЯ: «Наверное, endpoint возвращает JSON в таком формате...»
НУЖНО:  Создать reviews/task-<NNN>.blocked.md с описанием, чего не хватает.
```

Harness обработает BLOCKED корректно: оркестратор уточнит спеку (refine),
раздробит задачу (split), или передаст человеку (block).

## Чеклист перед завершением задачи

```
□ Каждый изменённый файл я ПРОЧИТАЛ перед редактированием
□ Каждая используемая функция/класс СУЩЕСТВУЕТ (проверено grep/rg)
□ Каждый импорт РЕЗОЛВИТСЯ (модуль существует в зависимостях/репо)
□ Изменения ТОЛЬКО в файлах из спеки задачи (+ обоснование для остальных)
□ Нет спекулятивного кода «про запас»
□ Гейты проекта ЗЕЛЁНЫЕ
```

## Связь с harness

- Конституция (`.cursor/rules/00-constitution.md`) уже содержит базовые
  правила заземления. Этот скилл — развёрнутая тактика выполнения.
- Anti-gaming guard физически блокирует правку защищённой зоны.
- Ревьюер проверяет заземление: выдуманные API, мёртвый код, отладочные логи.
- Эскалация модели (auto → kimi → glm) не поможет, если проблема — в
  галлюцинации, а не в сложности. Заземление критичнее мощности модели.
