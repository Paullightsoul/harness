# Шаблоны отчётов по задачам

Отчёт описывает **проделанную работу по задаче** (что изменилось в продукте/коде, что готово, что осталось).  
**Не писать** про оркестрацию, прогоны, агентов, control plane, run id, model, DAG и т.п.

## Файлы

| Файл | Назначение |
|------|------------|
| `harness-run-report.md` | Шаблон отчёта по YouTrack-задаче (имя историческое; содержание — про работу) |

## Куда складывать

В репозитории проекта:

```text
<repo>/harness_reports/<ISSUE_ID>/<YYYY-MM-DD>-<slug>.md
```

Пример: `harness_reports/ZYN-371/2026-07-22-flight-rework.md`

## YouTrack

1. Заполнить шаблон → сохранить в `harness_reports/<ISSUE>/…`.
2. **Комментарий** к issue: тот же текст (или сжатое резюме + путь к файлу) — язык задачи, не процесса.
3. **Описание** — сверху блок готовности (без упоминания tooling):

```markdown
<!-- harness-coverage:start -->
**Готовность:** NN% — обновлено YYYY-MM-DD
Источник: `harness_reports/<ISSUE>/<file>.md`
<!-- harness-coverage:end -->
```

Маркеры `harness-coverage` — технические для upsert; в видимом тексте только «Готовность» и путь к отчёту.

## Запрещено в тексте отчёта/комментария

- слова: harness, run, Task Tool, worker, reviewer, DAG, plan_hash, spool, ship_mode, orchestrator
- «как делали» / «через какой прогон»
- внутренние id диспатчей

Писать: что реализовано, какие endpoints/схемы/поведение, тесты/доказательства по смыслу, что осталось до 100%.
